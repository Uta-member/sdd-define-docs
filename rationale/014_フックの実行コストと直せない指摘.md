# フックの実行コストと「直せない指摘」

実プロジェクトでプラグインを使ったハーネス側レビューで出た2件への回答。どちらも「安全網そのものが作業の邪魔になる」種類の問題で、方法論の中身ではなく**実装の質**の問題。

## 問題1：Stop フックが毎ターン 33 秒（実測）

`trace-guard.sh` → `check-traceability.sh` が実測 33.5 秒（うち sys 15 秒）。原因は構造：

```sh
git ls-files | while read f; do grep -oE ... "$f"; done   # ファイル1件につき1プロセス
```

Windows のプロセス生成は 1回 80〜150ms かかる。数百ファイルのリポジトリなら、これだけで数十秒になる。しかも Stop フックなので、**発火条件を満たす間（implement 中でブランチにテスト差分がある間）は全ターンの終了に上乗せされる**。`/sdd:trace` 経由でも同じスクリプトを呼ぶので二重に払っていた。

### なぜこれが方法論の問題でもあるか

[[009_フローレビュー]] 総評でフックを「backstop」と位置づけた。backstop は**存在を忘れられる程度に安いこと**が前提条件で、毎ターン 33 秒はその前提を壊す。人間は遅い安全網を必ず外す（`--no-verify` の類）。外された安全網は無いのと同じで、[[013_クロスプラットフォームのシェル依存]] で嫌った「黙って消える安全網」に自分から近づく。

### 決定：走査は「git grep 一発 → awk 一発」に畳む

- **per-file ループを禁止する。** ファイルごと・AC-IDごとにコマンドを起こす構造を書かない。ループが要るなら awk の中に入れる。AC参照の収集はリポジトリ全体を `git grep -oE '@?AC[-_]...'` で1回なめ、`.feature`／テストの振り分けは awk が出力パスを見て行う。
- **差集合の報告も awk 1プロセス。** 「AC-IDごとに `awk` で参照ファイルを引く」ループが 26 件の指摘で 26 プロセスになっていた。畳んだ表2枚を awk に食わせて片付ける。
- **ref 探索は `for-each-ref` 1回。** `origin/HEAD → origin/main → … → master` を `rev-parse --verify` で5回叩いていたのを1回にする（`guard-frozen.sh` と同じ ref 群・同じ優先順を維持）。
- **Stop フック用に `--missing-only` モードを足す。** フックが判断に使うのは「テストの無いAC」だけ。規律チェック3種（design.md のID宣言／`implements:`／supersede）は `/sdd:trace` だけの関心事で、毎ターン走らせる理由がない。

実測：33.5s → **発火時 2.3s / 非発火時 0.9s**（`/sdd:trace` のフル実行は 3.6s）。

この制約はスクリプト冒頭に「性能：プロセス数がすべて」としてコメントで固定した。後から「1ファイルずつ丁寧に見る」リファクタで元に戻されるのが一番ありそうな劣化なので、理由（Windows のプロセス生成コスト、Stop フックの毎ターン性）まで書く。

## 問題2：`/sdd:trace` が「構造的に直せない指摘」を 26 件出し続ける

`## 見出し [REQ-…, AC-…]` のID宣言漏れ 26 件が、全部**マージ済みの design.md** だった。つまり：

- [[007_ドキュメント管理方針]] の write-once により変更禁止
- `guard-frozen.sh`（PreToolUse）が Edit/Write を実際に **deny** する

指摘に従おうとすると自分のフックに殴られる。しかもユニットが増えるほど単調増加し、**唯一の生命線である「テストの無いAC」を希釈する**（[[010_テスト妥当性ゲート]]・[[011_NFR検証ライフサイクル]] と同じ構図——ノイズは生命線を殺す）。

### 決定：ID宣言漏れは未凍結の design.md に限定する

凍結判定は `guard-frozen.sh` と同じ「デフォルトブランチに既に存在するか」を使う（refの並びも揃える。判定が2箇所で食い違うと、片方が「直せ」と言い片方が「触るな」と言う状態に戻る）。除外件数は `（凍結済み N 件は変更不可のため対象外）` と本文に出す——**黙って減らさない**（[[004_トレーサビリティ]]「黙って嘘をつかない」）。

なお他の5項目は凍結の影響を受けない：テストの無いAC・supersede 済み旧ID・`implements:` はいずれも living なコード側で直せるし、採番衝突はマージ済みでも異常として声を上げるべき。除外は宣言漏れ検査だけの話。

### 一般則

**フックとチェッカーは、受け手が実行できる指摘だけを出す。** 実行不可能な指摘は「厳しさ」ではなく単なるノイズで、実行可能な指摘の価値を下げる。凍結領域を持つ方法論では、チェッカー側も凍結を知っていなければならない。

## 反映先

- `scripts/check-traceability.sh`：走査を git grep + awk に再構成。`--missing-only` を追加。ID宣言漏れを未凍結 design.md に限定。性能制約をヘッダコメントで固定。
- `scripts/trace-guard.sh`：ref 探索を `for-each-ref` 1回に。`--missing-only` で本体を呼ぶ。`git diff <base>` が staged/unstaged 両方を含むことを使い差分取得を1回減らす。
- `skills/trace/SKILL.md`：ID宣言漏れの対象が未凍結のみである旨と、`--missing-only` はフック専用（スキルでは使わない）である旨を明記。
- `sdd-plugin/README.md`：フック行に実行コストを併記。
