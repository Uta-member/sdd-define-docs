# /sdd:trace — トレーサビリティチェック（非ブロック）

プレーンテキストIDと全文検索だけで成立する発見的チェック。**結果は報告であり、作業をブロックしない**（IDの書き忘れは「壊れる」のではなく「検索にヒットしなくなる」だけ＝優雅な劣化。ただし回帰網の穴だけは重大なので強調して報告する）。

## 手順

### 1. 機械チェック（スクリプト）
このSKILL.mdから見て `../../scripts/check-traceability.ps1` を実行する：

```
powershell -NoProfile -ExecutionPolicy Bypass -File "<プラグインルート>/scripts/check-traceability.ps1"
```

出力される差分：
- **テストの無いAC**（.featureにあるがテストコードに参照が無い）← **回帰の穴の候補。最重要**
- **存在しないACを指すテスト**（タグ側に無いIDをテストが参照）

### 2. AIレビュー（全文検索ベース）
スクリプトが拾えない規律の抜けを Grep で確認する：
- `{DOCS_DIR}/units/` 配下の design.md に `[REQ-` / `AC-` 宣言の無い節がないか
- 新規/変更ソースファイルの先頭に `implements:` 宣言があるか
- `supersedes:` 宣言があるのに旧AC-IDのテストが残っていないか（livingテストは最新IDを担ぐ）

### 3. 報告
- 差分をID付きの一覧で報告する。
- 「テストの無いAC」が残っている場合は、統合テストへの吸収が絶対条件であることを添えて修正を促す。
- 台帳（マトリクス）が欲しいと言われたら生成してよいが、「検索で再生成できるキャッシュであり正本ではない」旨を明記する。
