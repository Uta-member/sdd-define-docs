# /sdd:trace — トレーサビリティチェック（非ブロック）

プレーンテキストIDと全文検索だけで成立する発見的チェック。**結果は報告であり、作業をブロックしない**（IDの書き忘れは「壊れる」のではなく「検索にヒットしなくなる」だけ＝優雅な劣化。ただし回帰網の穴だけは重大なので強調して報告する）。

**実行タイミング**：単体でも呼べるが、通常は `/sdd:implement` の完了時と `/sdd:accept` のPR仕上げ前に走らせる。回帰網の穴の検知を毎サイクル最低一度は通すのが狙い。

**このスキルは全部スクリプトでやる。**チェック項目は6つとも純粋な grep 判定なので `check-traceability.sh` に機械化済み。**独自に Grep/Read で探索を足さないこと**——発見は機械判定と同じでコンテキストだけ食う（このスキルは以前トークン消費の最大要因だった）。

## 手順

### 1. スクリプトを実行する
このSKILL.mdから見て `../../scripts/check-traceability.sh` を実行する：

```
bash "<プラグインルート>/scripts/check-traceability.sh"
```

（`--missing-only` を付けると「テストの無いAC」だけを返す軽量モードになる。これは毎ターン走る Stop フック専用で、**このスキルでは付けない**——6項目を見るのがこのスキルの役目。）

チェックされる6項目：

| 項目 | 意味 |
|---|---|
| **テストの無いAC** | .featureにあるがテストコードに参照が無い ← **回帰の穴の候補。最重要** |
| 存在しないACを指すテスト | タグ側に無いIDをテストが参照（タグ漏れ or 廃止済みIDの残骸） |
| 採番衝突 | 同一AC-IDが複数の .feature に定義。名前空間ID `AC-<slug>-<n>` では構造的に起きないはずの異常で、slugの使い回し等を疑う安全網（→ 12 採番の衝突と直列化） |
| design.md の節のID宣言漏れ | `## 見出し [REQ-…, AC-…]` の宣言が無い節（逆引き検索にヒットしなくなる）。**未凍結の design.md だけが対象**——マージ済みは write-once で `guard-frozen.sh` が編集を deny するため、指摘しても直せないノイズにしかならない |
| 変更ソースの `implements:` 宣言漏れ | ブランチ基点との差分に含まれるプロダクションコードの先頭宣言 |
| supersede 済み旧IDを担ぐテスト | living テストは最新IDを担ぐ。旧IDはスナップショット内にだけ残るのが正 |

### 2. 報告
- スクリプトの出力をそのまま報告する。**解釈や再調査を足さない。**
- 「テストの無いAC」が残っている場合だけ、統合テストへの吸収が**【不変条件】**であることを添えて修正を促す。それ以外は優雅な劣化なので淡々と列挙するだけでよい。
- 台帳（マトリクス）が欲しいと言われたら生成してよいが、「検索で再生成できるキャッシュであり正本ではない」旨を明記する。
