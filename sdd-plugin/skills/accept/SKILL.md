# /sdd:accept — 受入テストとエビデンス凍結

## 前提

- `/sdd:implement` の**テスト妥当性ゲート（sdd-test-reviewer＋人間確認）を通過済み**であること。未通過なら停止して implement の完了条件に戻す。ここで凍結するエビデンスは「妥当なテストの実行結果」であることが前提。

## 手順

### 1. 自動受入テストの実行
- この作業単位のAC-IDを担ぐテスト（および回帰網全体）を実行する。
- 失敗したら `/sdd:implement` の手戻り判定（How→設計へ局所ループ／What→要件へ戻り再承認）に従う。

### 2. エビデンスの凍結
`{DOCS_DIR}/units/<作業単位>/evidence.md` に**凍結スナップショット**として記録する：
- 実行日時・コミットハッシュ・実行コマンド
- AC-IDごとの結果（pass/fail、手動の場合は実施者と結果）
- このファイルはマージ後変更禁止（write-once）。

### 3. 手動受入テスト
- 自動化できないAC（画面操作・外部環境が要るもの）は、手順のチェックリストを提示して**人間に実施を依頼**する。
- 結果を人間から聞き取り、evidence.md に追記してから凍結する。

### 4. PRの仕上げ（atomic co-change）
- **tasks.md（および開発レポート等の廃棄可能ファイル）を削除する。**
- PRに以下が全部そろっていることを確認する：
  - requirements.md / design.md / evidence.md（スナップショット）
  - .feature（テストコードの隣）
  - コード＋ユニットテスト＋統合テスト
  - 新規ADR（あれば）
- PR作成はユーザーの指示に従う（勝手にpush/mergeしない）。

### 5. 【必須】trace の最終チェック
PRを仕上げる前に **`/sdd:trace` を必ず実行する**（省略不可の必須ステップ）。モデルの生命線＝回帰網を守る唯一の機械チェックであり、implement時に一度走らせていてもマージ直前の最終状態で再確認する。
- 実行自体は必須だが、**結果はブロックしない**（trace の非ブロック方針は維持）。差分はID付きで報告する。
- ただし「テストの無いAC」が残っている場合は、回帰網の穴として強調して報告し、統合テストへの吸収を促す（原則その場で直しきる）。

### 6. 次へ
マージ後、次の作業単位は再び `/sdd:req` から。保守（機能追加・振る舞い変更・リファクタ・バグ修正）もすべて同じサイクル。
