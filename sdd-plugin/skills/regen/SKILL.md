# /sdd:regen — 現在仕様書の再生成

SDDでは「現在の全体仕様書」を維持しない。必要になったときだけ、**唯一の真実（ソース＋ユニットテスト＋統合テスト）から再生成**する。

## 手順

1. **入力は living のみ**：ソースコード、ユニットテスト・統合テスト（テスト名のAC-IDと `implements:` 宣言を手がかりに読む）、`{DOCS_DIR}/architecture.md`。
   - 過去のスナップショット（requirements.md / design.md / .feature）は**現在の状態の根拠にしない**（差分の履歴であって最新状態ではない）。Why の補足に ADR を参照するのはよい。
2. 読者をユーザーに確認する（監査向け／非技術者への引き継ぎ／外部提出などで粒度を変える）。
3. `{DOCS_DIR}/generated/spec-<yyyy-mm-dd>.md` に出力する。冒頭に明記：

   > この文書は <日付> のコミット <hash> 時点のソース＋テストから再生成されたキャッシュである。正本はソースコードとテストであり、本文書は陳腐化しても何も保証しない。

4. 構成の目安：機能一覧（テストが保証する振る舞いを、担いでいる最新AC-IDと共に）／アーキテクチャ概要（architecture.mdから）／主要な設計判断（ADRの現在有効なもの）。
